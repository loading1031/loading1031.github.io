# 세션 내용을 블로그 초안으로 캡처

블로그 레포: `/Users/seongmun/Documents/github-blog` (아래에서 `$BLOG` 로 표기)

이 스킬은 **어느 세션에서든** 호출된다. 지금 대화의 맥락을 그대로 가진 채 글을 쓰는 것이
가장 좋은 글이 나오는 시점이므로, 대충 메모만 남기지 말고 **읽을 수 있는 글을 완성**한다.
다만 `draft: true` 로 저장하므로 배포되지는 않는다.

## 1. 무엇을 남길지 정한다

이 대화를 되짚어서, 남길 가치가 있는 것 하나를 고른다. 기준은 하나다.

> **6개월 뒤의 내가 읽고 바로 써먹을 수 있는가.**

남길 만한 것:
- 문서에 안 나와 있거나 찾기 어려웠던 동작, 제약, 함정
- 처음 생각한 접근이 틀렸고 왜 틀렸는지 알게 된 경우
- 개념 하나를 제대로 이해하게 된 대화
- 여러 선택지를 비교하고 이유를 붙여 하나를 고른 판단

남기지 말 것:
- 공식 문서를 그대로 옮긴 내용 (링크 하나면 충분하다)
- 이 프로젝트에서만 통하는 설정값이나 일회성 삽질
- 결론 없이 "해봤다"로 끝나는 기록

**남길 게 없으면 없다고 말하고 끝낸다.** 억지로 만들지 않는다.

## 2. 회사 정보를 걷어낸다 (중요)

블로그는 **공개**되고, 이 스킬은 회사 프로젝트 세션에서도 호출된다.
글을 쓰기 전에 반드시 확인한다:

```bash
pwd && git remote -v 2>/dev/null | head -2
```

작업 디렉터리나 원격이 회사 것이면((회사) 등 개인 계정이 아닌 모든 곳),
글에서 다음을 전부 걷어낸다:

- 사내 코드 원문, 내부 모듈/테이블/필드 이름, 사내 URL·호스트·엔드포인트
- 서비스명, 고객사명, 고객 데이터, 지표 수치
- 토큰·키·자격증명 (일부만 남기는 것도 안 된다)

그리고 문제를 **일반화된 최소 재현 예제로 다시 쓴다.** 사내 코드를 익명화하는 게 아니라,
같은 원리를 보여주는 새 예제를 짓는다. 그렇게 다시 쓸 수 없는 내용이면 캡처하지 않는다.

판단이 애매하면 사용자에게 물어본다.

## 3. 사용자에게 짧게 확인한다

정리해서 한 번에 보여주고 확인받는다. 길게 인터뷰하지 않는다.

- **제목** (한글)
- **slug** (URL 이 된다. 영문 소문자 + 하이픈)
- **태그** — `study`(공부 기록) / `insight`(Claude 인사이트) / `til`(짧은 기록) 중 하나 이상
- **한 줄 요약** (목록에 보이는 description)

## 4. 글을 쓴다

Claude 답변을 그대로 붙여넣지 않는다. **이해한 내용을 내(사용자) 말로 다시 쓴다.**
"~인 것 같습니다", "도움이 되셨길 바랍니다" 같은 어시스턴트 말투를 남기지 않는다.
한국어로, 담백한 평서체(`~다`)로 쓴다.

기본 구조 — 내용에 안 맞으면 바꿔도 된다:

```markdown
어쩌다 이걸 알게 됐는지 두세 문장. 배경 설명을 길게 깔지 않는다.

## 문제

무엇을 하려다 뭐가 막혔는지. 가능하면 최소 재현 코드.

## 알게 된 것

핵심. 왜 그렇게 동작하는지까지 쓴다. 결론만 쓰면 나중에 응용이 안 된다.

## 정리

다음에 같은 상황을 만나면 무엇을 먼저 볼지, 한 문단.

## 참고

- [문서 제목](URL)
```

코드 블록에는 언어를 표시한다(` ```ts `). 확인하지 않은 코드는 넣지 않는다.

## 5. 저장한다

`$BLOG/scripts/blog.mjs` 로 만든다. 파일을 직접 쓰지 말고 이 스크립트를 쓴다
(frontmatter 형식과 태그 검증을 스크립트가 책임진다).

```bash
node scripts/blog.mjs new \
  --title "제목" \
  --slug my-post-slug \
  --tags study \
  --description "한 줄 요약" \
  --source "어떤 작업 중에 나왔는지 (예: 사이드 프로젝트 A 의 인증 붙이다가)" \
  --body-file - <<'EOF'
본문
EOF
```

`--source` 에는 **회사 프로젝트명이나 사내 정보를 쓰지 않는다.** 일반적인 표현으로 적는다.

## 6. 마무리

- 저장 경로와 미리보기 방법을 한 줄로 알린다:
  `npm run dev` → `http://localhost:4321/blog/<slug>/`
- **커밋도 푸시도 하지 않는다.** 발행은 블로그 레포에서 `/blog-publish` 로 한다.
- 원래 하던 작업으로 바로 돌아간다. 블로그 얘기를 더 늘어놓지 않는다.
