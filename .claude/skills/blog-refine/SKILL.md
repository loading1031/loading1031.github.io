# 초안 다듬기

캡처는 세션 맥락이 살아 있을 때 쓴 글이다. 이 단계는 **그 맥락이 없는 독자**의 눈으로
다시 읽는 것이 목적이다. 맥락을 아는 사람에게만 말이 되는 문장을 찾아낸다.

## 1. 대상 고르기

```bash
node scripts/blog.mjs list --drafts
```

인자로 slug 이 주어졌으면 그걸 쓰고, 아니면 목록을 보여주고 고르게 한다.

```bash
node scripts/blog.mjs show <slug>
```

## 2. 점검 항목

순서대로 본다. 고칠 게 없으면 없다고 말한다 — 억지로 손대지 않는다.

**말투**
- 어시스턴트 말투가 남아 있는가 (`~인 것 같습니다`, `~하시면 됩니다`, `도움이 되셨길`)
- 불필요한 도입부 ("이번 글에서는 ~에 대해 알아보겠습니다")
- 과장된 마무리 ("이제 완벽하게 이해했다")
- 평서체(`~다`)로 일관되는가

**내용**
- **결론이 앞에 있는가.** 배경 설명이 세 문단 이상 이어지면 잘라서 뒤로 보낸다.
- 왜 그렇게 동작하는지가 있는가. "이렇게 하면 된다"만 있으면 응용이 안 된다.
- 이 세션에서만 통하는 말이 남아 있는가 (`아까 그 파일`, `위에서 본 것처럼`)
- 6개월 뒤의 사용자가 읽고 바로 써먹을 수 있는가

**보안** — 캡처 때 걸렀더라도 다시 본다. 발행하면 되돌리기 어렵다.
- 사내 코드/식별자/URL/서비스명/고객 정보/수치
- 토큰, 키, 자격증명, 개인 경로(`/Users/seongmun/...` 같은 것도 굳이 남길 필요 없다)

**코드와 링크**
- 코드 블록에 언어 표시가 있는가
- 코드가 실제로 도는가. 가능하면 임시 디렉터리에서 실행해 확인한다.
- 링크가 살아 있는가:
  ```bash
  curl -s -o /dev/null -w '%{http_code} %{url_effective}\n' -L <URL>
  ```

**frontmatter**
- `description` 이 목록에서 읽혔을 때 클릭할 만한가 (제목 반복이 아니라 내용 요약)
- `tags` 가 맞는가 — `study` / `insight` / `til`
- `pubDate` — 캡처한 날 그대로 둘지, 발행일로 바꿀지 확인한다

## 3. 고치기

고친 내용을 **어디를 왜 고쳤는지** 짧게 보고한다. 전문을 다시 출력하지 않는다.
크게 다시 쓸 만한 부분은 먼저 물어보고 진행한다.

`draft: true` 는 그대로 둔다. 내리는 것은 `/blog-publish` 의 일이다.

## 4. 마무리

```bash
node scripts/blog.mjs doctor
```

통과하면 "발행 준비됨. `/blog-publish <slug>`" 라고 알린다.
